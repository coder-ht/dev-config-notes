# Baseline 项目经验总结

本文档只记录能够指导 Baseline 同类任务的稳定判断、边界和验证方式，不记录单次应用、版本号或执行状态。

## 前端部署版本升级最小流程

- 适用场景：升级 `component/fe.yaml` 中用户指定前端应用的部署版本。
- 判断与做法：先确认用户指定的应用范围，读取各应用当前分支权威版本文件，并按 `package` 名称与 Baseline 对应条目逐一比较；版本一致时保持无修改，版本不一致时只把该应用条目更新为其当前真实版本。需要写入时先确认 Baseline 工作区和远端基线，再按目标 `package` 上下文精确修改。
- 边界与验证：不得根据版本差异自行增加、删除或调整应用范围，也不得推断目标版本；只要求更新 Baseline 时不顺带修改应用仓库。完成后检查目标差异、`git diff --check` 和 YAML 解析结果；执行期间仓库状态变化时重新读取后再继续。
