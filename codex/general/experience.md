# 通用经验总结

本文档记录所有环境都适用的 Codex 协作、编码、规则维护和仓库操作经验。

## 2026-07-13 按收益使用 subagent

- 场景：需要统一 Codex 的任务协作方式。
- 做法：任务可独立拆分、并行收益明显且当前运行策略允许时再使用 subagent；明确输入、输出和边界后委派，由主 agent 负责原始证据核验、整合和最终验证。
- 注意：简单任务、强耦合修改和统一判断任务直接执行；subagent 失败或超时不能阻塞主流程。

## 2026-07-20 经验归类与抽象质量门槛

- 场景：需要避免任务结束时遗漏经验归类，也要避免把一次任务的对象、过程和结果机械沉淀为特例经验。
- 做法：任务开始时按关键词检索并读取命中经验；结束前判断优化、追加或无需变更。新增或优化前隐去本次对象、ID、地址、数量和时间，确认剩余内容仍能指导同类任务，再提炼适用条件、判断方法、风险边界和验证方式。
- 注意：不要求全文反复读取，也不强制新增；一次性事实和执行状态留在任务结果中，近义结论优先合并。写入后复读目标条目，检查归属、抽象层级、重复性和敏感信息。

## 经验归属规则

- 所有环境都适用的经验写入本文件。
- 只和某个环境的路径、项目、配置、账号、机器状态相关的经验，写入对应环境目录下的 `experience.md`。
- 不确定归属时，先询问用户，不要随意写入通用经验。

## 2026-07-09 Codex 规则迁移与路由

- 场景：需要把 Codex 全局规则放入仓库，方便不同机器的新 Codex 复用。
- 做法：`AGENTS.md` 只保留环境路由逻辑，具体规则拆到 `codex/general/` 与 `codex/envs/<env>/`。
- 复用：任务开始时先读取 `CODEX_WORK_ENV`，始终加载通用规则/经验，再按环境加载对应规则/经验。
- 注意：写入经验前必须判断归属，通用经验写入 `codex/general/experience.md`，环境专属经验写入对应环境目录。
- 约定：入口 `AGENTS.md` 必须直接读取当前环境 `dev-config-notes` 项目中的规则文件，不读取本机 `~/.codex/codex/` 副本。

## 2026-07-09 Codex 规则双向同步

- 场景：用户要求同步或备份 Codex 规则，需要同时保留仓库最新内容和本机尚未入库的有效规则。
- 做法：同步与备份执行同一流程；先校验环境、检查工作区并获取远端最新状态，以远端规则为基线逐项合并本机有效改动，再同步入口、验证、提交并推送本次 `codex/` 变更。
- 注意：不能用任一方旧副本整体覆盖另一方；双方修改同一规则且语义不明确时停止询问。`~/.codex/codex/` 镜像不参与同步，认证和运行状态文件不进入仓库。

## 2026-07-09 Codex 环境变量强制要求

- 场景：用户要求 Codex 必须配置环境变量后才能正常工作。
- 做法：`CODEX_WORK_ENV` 是必需环境变量，当前支持 `ghy`、`home-windows` 和 `home-wsl`；缺失或未知时必须停止具体任务并提示用户配置。
- 注意：规则维护任务可用于落地这条约束；后续普通任务、同步、备份、提交、推送等都必须先确认 `CODEX_WORK_ENV` 有效。

## 2026-07-09 Codex 执行说明与经验参考强化

- 场景：用户要求加强经验总结、经验参考、执行前计划说明和执行后说明的规则约束。
- 做法：任务前按关键词检索相关经验，需要执行计划时说明命中情况；任务后判断优化、追加或无需变更。只有形成同类任务可复用结论时才新增。
- 注意：经验只能辅助缩小范围，不能替代当前真实文件、命令输出、配置或接口响应；不机械全文读取，也不把一次性对象、过程或结果写成经验。

## 2026-07-09 接口请求信息记录边界

- 场景：用户提供测试环境 curl，希望记录接口地址、请求头和 token 信息。
- 做法：按用户要求记录 Host、路径、Header 名称、tenant、terminal、content-type、Referer、Authorization、Cookie 和 token 相关信息。
- 注意：记录测试环境请求信息时，优先保留接口复用所需字段。

## 2026-07-09 前端项目 ga&gc 版本号规则

- 场景：对前端应用执行 `ga&gc` 或等价暂存提交流程。
- 做法：提交前检查仓库或目标应用是否明确要求升级版本号；有要求时只升级本次应用。
- 注意：仓库没有版本升级约定时，不因普通提交自动修改 `package.json`。

## 2026-07-09 执行前风险分级确认

- 场景：需要在执行效率与高风险操作确认之间保持边界。
- 做法：范围明确、可回滚的普通本地修改在说明后直接执行；远端写入、生产操作、部署、推送、破坏性操作、较大范围修改或存在覆盖风险时先列计划并等待确认。
- 注意：用户已明确要求直接执行时无需重复确认，但仍要遵守安全和权限边界。

## 2026-07-10 Codex 全局免确认与全权限配置

- 场景：用户希望后续 Codex 会话无需逐条确认，且不受沙箱限制。
- 做法：在全局 `~/.codex/config.toml` 设置 `approval_policy = "never"` 与 `sandbox_mode = "danger-full-access"`，并用 `codex.cmd --strict-config --version` 校验。
- 注意：该组合允许自动执行未受沙箱保护的命令，仅应在用户明确授权且环境本身有额外防护时使用。

## 2026-07-10 应用安装经验沉淀

- 场景：用户要求安装、迁移或升级应用。
- 做法：执行前检索当前 `dev-config-notes` 仓库的通用和环境经验；未命中时，在安装验证后提炼可复用的安装判断、兼容性边界或验证方法，通过同类任务复用测试后再写入正确归属文件。
- 注意：一次性的版本号、下载地址、临时路径和安装结果不单独沉淀；环境专属安装方式不能写入通用经验；未经用户要求，不因更新经验自动提交或推送。

## 2026-07-13 Codex 规则与经验同步备份的副本校验

- 场景：本机残留的规则镜像可能落后于权威仓库。
- 做法：以 `dev-config-notes/codex/` 为唯一规则源，只同步 `~/.codex/AGENTS.md` 入口；旧的 `~/.codex/codex/` 镜像不参与读取、同步或备份。
- 注意：不能用旧副本覆盖仓库；无实际规则差异时不创建空备份提交。

## 2026-07-14 项目级规则按仓库根路径路由

- 场景：多个项目各自维护规则和经验，需要避免项目规则互相串载。
- 做法：根据完整仓库根路径或其子目录精确映射到 `codex/projects/<project>/`，一次只加载匹配到的一个项目。
- 注意：不要根据当前子目录名称猜测项目；未匹配项目时只加载通用规则和环境规则。

## 2026-07-15 外部系统写入回读验证

- 场景：通过 MCP、API、数据库客户端或其他工具修改外部系统，工具返回成功但实际结构或展示可能不符合预期。
- 做法：写入前读取并保留原结构和关联引用；写入后使用独立读取或查询核对目标对象、关键字段、引用关系和同批次影响范围。
- 注意：成功响应只代表请求被接受，不能替代结果验证；发生 AI 失误时需记录现象、根因、错误做法、正确做法、影响范围和验证方式。

## 2026-07-15 Bash 脚本兼容 sh 调用

- 场景：含 `pipefail`、`[[ ... ]]` 等 Bash 语法的脚本被用户通过 `sh script.sh` 调用，或粘贴缩进导致 shebang 前存在空格。
- 做法：确保 `#!` 从文件首字节开始，并在使用 Bash 专属语法前检测 `BASH_VERSION`、通过 `exec bash "$0" "$@"` 自动切换解释器；使用用户原始调用方式做真实验证。
- 注意：不能简单删除 `pipefail`，否则导出压缩等管道可能掩盖上游失败；`pipefail` 下游提前退出会使上游收到 SIGPIPE 并返回 141，需要让读取端消费完整输入；动态匹配反引号时不要将其直接放进 Shell 双引号，应通过 `printf` 或单引号程序生成字面量，避免触发命令替换。最后同时执行 `bash -n`、用户原始调用方式、产物完整性和校验文件回读。

## 2026-07-17 WSL 生成 Windows 桌面 PDF

- 场景：在 WSL 中生成学习资料并放到 Windows 的 D 盘桌面。
- 做法：用 Windows PowerShell 查询桌面路径，创建 `D:\desktop\学习资料\<技术>` 目录，再用 Windows Chrome headless 将 WSL HTML 打印为 PDF。
- 注意：WSL 可能没有 `/mnt/d` 挂载；通过 PowerShell 的 Windows 路径和 `\\wsl.localhost\<发行版>` 访问源 HTML，并独立检查 PDF 文件大小与时间。

## 2026-07-21 业务数据接口优先

- 场景：执行环境数据查询、配置维护或联动规则任务，不清楚业务接口及其真实参数。
- 做法：默认先调用业务接口；调用方式依次从既有经验、前端真实请求和后端 Controller/参数模型中核对，写入后再通过查询接口独立回读。
- 注意：接口不可用或无法覆盖目标时才降级到数据库等数据源，并说明原因与影响；规则、流程和联动修改尤其要避免直接改库绕过校验、事件与缓存。

## 2026-07-21 本地微应用入口切换与端口冲突

- 场景：主应用需要临时加载本地微应用验证修改，但预设开发端口已被其他应用占用。
- 做法：先读取监听进程、工作目录和页面标识确认端口对应的真实应用；不停止用户现有进程，选择空闲端口，并同步修改微应用开发服务的 `port/origin` 与主应用加载入口 `entry`。
- 注意：HTTP 200 不能证明加载了目标应用，还要核对页面标题、根节点或源码入口；本地验证配置不得扩散到测试或正式环境。
